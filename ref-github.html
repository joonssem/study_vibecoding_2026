교사가 GitHub을 쓸 때의 장단점

먼저 밝혀 둡니다 아래 장단점은 대부분 교재가 직접 말한 것이 아니라 작성자 판단입니다. 교재와 관련된 사실만 따로 표시했습니다. 근거는 서점 목차·소개문 정리 노트뿐이고 본문은 확인하지 못했습니다. 요금·정책은 바뀔 수 있으니 공식 안내를 확인하세요.

먼저 알아둘 사실

  • 교사 대상 도서에서 GitHub 비중은 작습니다. 캔버스·캔바·앱스 스크립트는 도구 안에서 링크가 나와 GitHub이 필요 없기 때문으로 보입니다. 앱을 학급 밖으로 공개하거나 서비스처럼 키울 때 GitHub이 등장합니다. 목차 근거 작성자 판단
  • 『교육과정을 코드로 옮기다』 시리즈는 GitHub Pages로 index.html을 배포합니다. 이 연수와 같은 방식입니다. 목차 근거
  • 많은 책에서 GitHub은 Vercel 같은 서비스로 자동 배포하는 입구로 쓰입니다. 목차 근거

장점

장점설명
무료이고 설치가 필요 없다웹 화면에서 가입하고, 코드를 붙여넣고, 배포까지 끝냅니다.
고정된 공개 주소가 생긴다학생·동료에게 링크 하나로 공유합니다. 수정해도 주소가 그대로입니다.
이력이 남는다고치기 전 상태로 돌아갈 수 있어 실수가 두렵지 않습니다.
도구와 무관하다제미나이·ChatGPT·Claude·안티그래비티 어디서 만든 코드든 같은 방식으로 올립니다.
다음 단계로 이어진다이후 Vercel 같은 서비스로 옮겨 갈 때도 같은 저장소를 쓸 수 있습니다.

단점과 주의점

단점설명
코드가 공개된다Public 저장소는 누구나 코드를 볼 수 있습니다. 학생 이름·번호, API 키, 비밀번호는 절대 넣지 않습니다.
서버 기능이 없다Pages는 정적 파일만 올립니다. 여러 사람이 같은 데이터를 보거나 AI 기능에 API 키를 쓰는 앱은 별도 구조가 필요합니다.
용어와 화면이 낯설다저장소(repository), Commit 같은 말과 영어 화면이 처음엔 어렵습니다.
학교 환경에서 막힐 수 있다가입 인증 메일 수신, 학교망에서의 접속 여부를 미리 확인해야 합니다.
반영이 즉시 되지 않는다첫 배포는 1~2분 걸릴 수 있고, 수정 후에는 강력 새로고침(Ctrl+Shift+R)이 필요할 수 있습니다.
작은 실수로 404가 난다파일명 index.html의 대소문자, 저장소 공개 설정, Branch 선택 등이 원인입니다.
계정이 개인 소유다학교 계정이 아니라 개인 계정에 앱이 쌓입니다. 이직·계정 분실 시 관리 문제가 있습니다.
고급 기능이 많아 보인다브랜치, Actions 등은 이 연수 범위가 아닙니다. 보이더라도 무시해도 됩니다.
비공개 저장소는 조건이 다를 수 있다비공개 저장소에서 Pages를 쓸 수 있는지, 조건이 무엇인지는 정책이 바뀔 수 있으니 공식 안내를 확인하세요.

그래서 어떻게 쓰나

  • 이 연수는 정적이고, 키가 없고, 학생 정보가 없는 앱만 GitHub Pages에 올립니다.
  • 이 조건을 벗어나면(데이터 공유, AI 기능, 프레임워크 사용) Pages를 넘어서는 구조가 필요합니다. 방향은 다음 단계에서 소개합니다.
꼭 지켜 주세요 학생 개인정보(이름·번호·평가 결과)와 API 키·비밀번호는 앱 코드와 저장소에 넣지 않습니다. GitHub Pages는 공개 주소이고, 배포하면 코드 전체가 누구에게나 보입니다.
