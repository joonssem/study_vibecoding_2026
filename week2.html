2회차. 내가 만든 웹앱, AI와 함께 다시 고쳐 보기

1회차에 만든 내 앱을 가져와 OpenCode에게 말로 요청해 고쳐 봅니다. 작게 바꾸고, 확인하고, 다시 요청해 보세요.

2026년 11월 17일 (화) 15:00~16:00

오늘의 목표 내 앱을 두세 번 고쳐 보고 다음에 바꾸고 싶은 점을 떠올립니다. 내 컴퓨터에서 수정 결과를 확인하면 성공입니다. 인터넷 주소에 다시 올리기는 시간이 남으면 해 봅니다.

시작하기 전에

  • 1회차에 만든 GitHub 저장소와 웹앱 주소를 준비합니다.
  • 앱에서 바꾸고 싶은 작은 점 한 가지를 떠올립니다. 예: 버튼을 크게 만들기, 퀴즈 점수 표시하기
  • OpenCode를 사용할 PC를 준비합니다. OpenCode 설치와 무료 모델 연결은 진행자의 안내를 따릅니다.
꼭 지켜 주세요 AI에 전달할 파일과 공개 저장소에 실제 학생 이름·번호·평가 결과, 비밀번호, API 키를 넣지 않습니다. Public 저장소의 코드는 다른 사람도 볼 수 있습니다. 연습할 때는 가상의 자료를 사용합니다.

1. OpenCode와 Git 준비하기

OpenCode를 실행하고 진행자의 안내에 따라 AI 모델을 연결합니다. 교육용 공용 노트북의 게스트 계정에서 OpenCode와 Git을 설치할 수 있음을 확인했습니다.

무료 모델 연결 안내 OpenCode 프로그램과 AI 모델 사용은 별개입니다. 사용할 무료 모델의 연결 방법·인증 조건·사용 한도는 연수 전에 확인 중이며, 진행자가 확인한 방법을 안내합니다. 유료 ChatGPT 구독은 필요하지 않습니다. 설치 또는 연결이 막히면 진행자에게 알려 주세요.

OpenCode에 Git 확인과 설치를 부탁할 수 있습니다. 실행할 내용을 확인하고 진행자와 함께 진행하세요.

이 Windows PC에서 Git이 설치되어 있는지 확인해 줘. 설치되어 있지 않다면 설치 방법을 알려 주고, 실행하기 전에 나에게 확인을 받아 줘. 설치가 끝나면 Git이 정상적으로 실행되는지도 확인해 줘.

Windows에서 설치 권한을 묻거나 설치 후 OpenCode를 다시 열어야 할 수 있습니다.

2. 내 앱을 컴퓨터로 가져오기

  1. GitHub에 로그인하고 1회차에 만든 저장소로 이동해 주소를 복사합니다. 저장소는 파일을 보관하는 곳이고, GitHub Pages 주소는 앱을 열어 보는 주소입니다.
  2. OpenCode에 아래처럼 요청해 저장소를 작업 폴더로 가져옵니다. 이 과정을 clone이라고 합니다.
내 GitHub 저장소 [여기에 저장소 주소 붙여넣기]를 컴퓨터의 작업 폴더로 가져와 줘. 실행하기 전에 저장할 위치를 알려 주고 확인을 받아 줘. 가져온 뒤 index.html이 있는지 확인해 줘.

가져온 폴더를 OpenCode에서 열고 index.html을 확인합니다. 수정 전에 폴더를 복사해 원본으로 보관하세요. 컴퓨터에서 고친 내용은 GitHub에 올리기 전까지 공개 주소에 반영되지 않습니다.

가져오기가 막히면 진행자와 함께 저장소의 Code → Download ZIP으로 파일을 받아 압축을 풀어도 됩니다. ZIP은 GitHub와 연결되지 않으므로 나중에 Git으로 바로 올릴 수는 없습니다. 이 경우 아래의 웹 업로드 방법을 사용하세요.

3. AI에게 내 앱 설명 부탁하기

아래 문장을 복사해 OpenCode 대화창에 입력합니다. 설명을 읽으며 내가 만든 앱이 맞는지 확인하세요.

이 폴더의 index.html을 읽고, 이 앱이 어떤 일을 하는지 초등학교 교사에게 쉬운 말로 설명해 줘. 화면의 주요 버튼과 각각의 기능을 알려 줘. 아직 파일은 수정하지 마.

4. 하나씩 고치고 확인하기

  1. 아래 예시처럼 한 번에 한 가지를 요청합니다. 내 앱에 맞게 바꿔 적어도 됩니다.
  2. OpenCode가 파일 수정이나 명령 실행을 허용할지 묻는다면 내용을 읽고 진행자와 함께 확인합니다.
  3. 수정이 끝나면 작업 폴더의 index.html을 브라우저로 열고 바뀐 점과 기존 버튼이 작동하는지 확인합니다. 이미 열려 있다면 새로고침합니다.
  4. 결과를 보고 다른 점을 요청하거나, 원하는 모습이 될 때까지 다시 설명합니다.

첫 번째 수정 예시

index.html에서 시작 버튼의 글자를 “시작하기”로 바꾸고 버튼을 조금 더 크게 해 줘. 다른 기능과 디자인은 그대로 유지해 줘. 수정한 내용과 브라우저에서 확인할 방법을 알려 줘.

퀴즈에 점수 표시하기

이 퀴즈 앱에서 정답을 맞힐 때마다 점수가 1점씩 올라가고 화면에 현재 점수가 보이도록 index.html을 수정해 줘. 다시 시작할 때는 점수가 0점이 되게 해 줘. 기존 퀴즈 기능은 유지하고, 학생의 이름이나 점수는 인터넷으로 전송하거나 저장하지 마. 수정 후 확인할 방법도 알려 줘.

한 번 더 요청하기

점수는 보이는데 글씨가 작아서 교실 뒤에서는 잘 보이지 않을 것 같아. 점수 글씨만 더 크고 잘 보이게 바꿔 줘. 다른 기능은 유지해 줘.

뜻대로 되지 않을 때

수정한 뒤에 [어떤 버튼을 눌렀는지] 했더니 [실제로 나타난 현상이나 오류 문구]가 나왔어. 원인을 확인하고 고쳐 줘. 원래 기대한 결과는 [원하는 동작]이야. 수정한 뒤 내가 확인할 방법도 알려 줘.

잘못 바뀌었다면 보관한 원본 폴더를 확인하거나 진행자에게 도움을 요청하세요. 문제 해결 안내도 참고할 수 있습니다.

5. 시간이 남으면: 수정한 앱 다시 공개하기

  1. 올리기 전, 파일에 학생 개인정보와 비밀번호·API 키가 없는지 다시 확인합니다.
  2. clone한 폴더에서 작업했다면 OpenCode에 아래처럼 요청합니다. GitHub 인증과 업로드 과정은 진행자와 함께 확인합니다.
이 프로젝트에서 바뀐 파일을 보여 주고, GitHub에 올릴 내용을 설명해 줘. 학생 개인정보나 비밀번호, API 키가 있는지도 확인해 줘. 커밋하거나 푸시하기 전에 나에게 확인을 받아 줘.

확인한 뒤 OpenCode에 커밋과 푸시를 요청합니다. Commit은 변경 내용을 이력에 기록하고, push는 그 기록을 GitHub에 올리는 것입니다. GitHub의 History에서 이전 기록을 볼 수 있습니다. 인증이 필요하면 진행자의 안내에 따라 GitHub 로그인 화면에서 직접 처리하고 비밀번호나 인증 코드를 AI 대화창에 입력하지 않습니다.

  1. 배포가 반영될 때까지 기다린 후 기존 GitHub Pages 주소를 열고 새로고침하여 바뀐 점을 확인합니다. 보이지 않으면 잠시 기다린 뒤 다시 확인하세요.

GitHub 인증과 OpenCode를 통한 푸시는 공용 노트북에서 추가 확인이 필요합니다. 막히거나 ZIP으로 작업했다면 GitHub 저장소의 기존 index.html이 있는 위치에서 Add file → Upload files로 수정 파일을 올리고 Commit changes를 누를 수 있습니다. 다른 파일도 수정했다면 필요한 파일을 같은 위치에 함께 올립니다. 시간이 부족하면 로컬에서 확인한 상태로 두고 진행자와 함께 살펴보세요. 배포 가이드
