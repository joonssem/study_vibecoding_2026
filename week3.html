3회차. Google Antigravity로 내 앱 발전시키기

2026년 11월 24일 (화) 15:00~16:00 · 5-2 교실

1회차에는 내 웹앱을 GitHub에 올렸고, 2회차에는 OpenCode로 코딩 에이전트에게 수정을 요청해 보았습니다. 3회차에는 학교 대여 노트북(Intune 게스트 모드)에 Google Antigravity를 직접 설치하고, 개인 Gmail 계정으로 로그인해 연수 이후에도 혼자 바이브코딩을 이어갈 수 있는 환경을 만듭니다. 내 GitHub의 2주차 완성본을 가져와 수정하고 다시 push하는 흐름을 익힌 뒤, 교실 PC에서 개인정보와 API 키를 안전하게 다루는 방법까지 연습합니다.

오늘의 목표 ① 대여 노트북(게스트 모드)에 Antigravity를 설치하고 개인 Gmail·GitHub 로그인을 마칩니다.
② Antigravity의 도움으로 Git for Windows를 설치하고, 내 GitHub의 2주차 완성본을 가져옵니다.
③ 바이브코딩으로 수정·확인하고 push까지 완주한 뒤, 로컬 JSON 저장 또는 안전한 Gemini API 키 연결을 연습합니다.

오늘의 흐름

분활동

10~152~3단계: GitHub 로그인 + Antigravity로 Git for Windows 확인·설치
15~224단계: 내 GitHub에서 2주차 완성본 가져오기(clone / pull) 및 앱 설명 확인
22~385단계: Antigravity에서 바이브코딩으로 수정하고 브라우저 실행·오류 해결
38~50선택 실습: 교실 PC 안전 활용 (트랙 A: 로컬 JSON 저장 / 트랙 B: Gemini API 키 안전 보관)
50~56.gitignore·개인정보·API 키 점검 후 commit & push로 GitHub 반영

준비물

  • 학교 대여 노트북 (Intune 게스트 모드 로그인) 또는 개인 노트북
  • 개인 Gmail(Google) 계정 (학교 Education Plus 계정으로는 Antigravity를 쓸 수 없습니다. 2단계 인증용 휴대폰도 함께 준비해 주세요.)
  • GitHub 계정과 1·2회차에 만든 앱 저장소
  • 앱에서 고치거나 추가하고 싶은 점 한 가지 (예: 잘못된 그림 고치기, 게임에 선택 기능 추가하기, 연산 연습 문제 만들기)
  • (트랙 B 선택 시) Gemini API 키를 발급받을 수 있는 Google 계정 (교육용 계정은 기관 설정에 따라 제한될 수 있으므로 개인 계정도 함께 준비하면 안전합니다.)

1. Antigravity 설치하고 개인 Gmail로 로그인하기 0~10분

  1. 학교 대여 노트북에 Intune 게스트 모드로 로그인합니다.
  2. 브라우저에서 Google Antigravity 다운로드 페이지를 열어 Windows용 설치 파일을 내려받고 설치합니다.
  3. Antigravity를 실행한 뒤 개인 Gmail 계정으로 로그인합니다.
  4. 영어 메뉴가 낯설어도 괜찮습니다. 오늘은 ① 왼쪽 파일 목록, ② 가운데 코드·변경 확인 화면, ③ AI 대화창 세 곳만 살펴봅니다.

2. GitHub에 로그인하기 10~12분

  1. 브라우저에서 GitHub에 로그인합니다.
  2. 1·2회차에 작업한 내 앱 저장소로 들어가 주소창의 저장소 주소(예: https://github.com/아이디/저장소이름)를 복사해 둡니다.

3. Antigravity에게 Git for Windows 설치 부탁하기 12~15분

게스트 모드 노트북에는 Git이 설치되어 있지 않을 수 있습니다. 아래 요청문을 복사해 Antigravity AI 대화창에 붙여넣고, 실행 전 안내를 확인하며 설치를 진행합니다.

이 Windows PC(게스트 계정)에 Git for Windows가 설치되어 있는지 확인해 줘.
설치되어 있지 않다면 설치 방법을 안내하고, 명령을 실행하기 전에 나에게 확인을 받아 줘.
설치가 끝나면 Git이 정상적으로 실행되는지 버전 확인까지 해 줘.

설치 과정에서 권한 확인 창이 뜨거나, 설치 후 Git을 인식하기 위해 Antigravity를 한 번 닫았다가 다시 열어야 할 수 있습니다.

4. 내 GitHub에서 2주차 완성본 가져오기 (pull / clone) 15~22분

2단계에서 복사한 저장소 주소를 아래 요청문에 넣어 2주차 완성본을 작업 폴더로 가져옵니다. 이 노트북에 처음 내려받을 때는 clone으로 가져오고, 이미 내려받은 폴더가 있을 때는 pull로 최신 상태를 맞춥니다.

내 GitHub 저장소 [여기에 2주차 저장소 주소 붙여넣기]의 최신 코드를 이 PC의 작업 폴더로 가져와 줘.
이 PC에 폴더가 없으면 git clone으로 내려받고, 이미 있으면 git pull로 최신 변경 사항을 반영해 줘.
실행 전에 저장할 폴더 위치와 명령어를 알려 주고 내 확인을 받아 줘.
가져온 뒤에는 아직 코드를 수정하지 말고, 이 앱이 어떤 기능을 하는지와 내가 브라우저에서 실행해 확인하는 방법을 한국어로 쉽게 설명해 줘.

폴더를 가져온 뒤 Antigravity에서 해당 폴더를 열어 index.html이 보이는지 확인합니다.

5. Antigravity에서 바이브코딩 진행하기 22~38분

  1. 한 번에 한 가지씩 원하는 변경 사항을 설명합니다. Antigravity가 파일 수정이나 명령 실행 승인을 물으면 내용을 한 번 읽고 허용합니다.
  2. 수정이 끝나면 내 컴퓨터 브라우저에서 앱을 열어 바뀐 점과 기존 기능이 정상 작동하는지 확인합니다.
  3. 결과가 기대와 다르거나 오류가 나면 나타난 상황을 그대로 알려 주고 다시 요청합니다.

수정 요청 예시

지금 앱에서 [바꾸고 싶은 부분: 예) 잘못된 그림 / 게임 시작 전 난이도 선택 버튼 / 연산 연습 문제]을 [원하는 모습]으로 수정해 줘.
다른 기존 기능은 그대로 유지하고, 수정이 끝나면 내 컴퓨터 브라우저에서 확인하는 방법도 알려 줘.

뜻대로 되지 않을 때

수정한 뒤에 [어떤 동작]을 했더니 [실제로 나타난 현상이나 오류 문구]가 나왔어.
원인을 쉽게 설명하고 고쳐 줘. 내가 기대한 동작은 [원하는 결과]야.

6. 교실 PC에서 안전하게 쓰기 (선택 실습) 38~50분

GitHub Pages는 누구나 볼 수 있는 공개 주소입니다. 학생 개인정보가 필요하거나 AI(API 키)를 연결하고 싶다면, 코드만 GitHub로 관리하고 실제 실행과 민감한 데이터·키는 내 교실 PC에만 두는 방식을 연습합니다.

트랙 A. 개인정보가 있는 앱: 교실 PC 로컬 실행 + JSON 파일 저장

학생 이름·번호·평가 기록처럼 공개하면 안 되는 데이터는 인터넷이나 GitHub에 올리지 않습니다. 앱의 빈 틀(코드)만 GitHub에 두고, 각자 교실 PC에서 앱을 실행해 데이터를 JSON 파일로 저장(내보내기)하고 다시 불러오기 하도록 만듭니다.

  • 실제 학생 데이터는 교실 PC의 로컬 폴더(예: 문서·바탕화면)에 .json 파일로 보관합니다.
  • 실수로 데이터 파일이 GitHub에 올라가지 않도록 .gitignore 파일에 JSON 데이터 파일(또는 data/ 폴더)을 등록합니다.
이 웹앱은 학생 개인정보 이슈를 피하기 위해 내 교실 PC에서만 실행해서 쓸 거야.
데이터를 서버나 인터넷으로 보내지 말고, 화면에 '데이터 저장(JSON 내보내기)' 버튼과 '데이터 불러오기(JSON 열기)' 버튼을 만들어 교실 PC에 JSON 파일로 저장·복원할 수 있게 수정해 줘.
또 연습 중 만든 실제 데이터 JSON 파일이 실수로 GitHub에 올라가지 않도록 .gitignore 파일도 함께 설정해 줘.

트랙 B. AI 기능이 필요한 앱: Gemini API 키 안전 보관 및 연결

웹앱에 Gemini AI 기능을 붙일 때 API 키를 코드(index.html)나 GitHub 저장소에 적으면 누구나 키를 볼 수 있어 절대 안 됩니다. 교실 PC나 개인 PC에만 키를 보관하며 안전하게 호출하는 두 가지 방법 중 상황에 맞는 방식을 연습합니다.

  • 방법 1 (로컬 .env 파일 보관 — 권장): 교실 PC 폴더에 .env 파일을 만들어 GEMINI_API_KEY를 저장하고, .gitignore에 .env를 추가해 GitHub 업로드를 원천 차단합니다. Antigravity가 만든 간단한 로컬 실행 스크립트로 교실 PC에서 앱을 실행합니다.
  • 방법 2 (브라우저 입력 방식 — 단일 HTML 유지 시): 코드에는 키를 넣지 않고, 앱 화면에 API 키 입력칸을 두어 내 브라우저(localStorage 또는 창을 닫으면 사라지는 sessionStorage)에만 저장해 사용합니다. 키 삭제 버튼을 반드시 함께 둡니다.
교육용 계정 API 키 참고 교육용 Google 계정은 학교·교육청 관리자 정책에 따라 Google AI Studio의 Gemini API 키 발급이 제한될 수 있습니다. 발급이 막혀 있다면 개인 Google 계정의 API 키로 먼저 구조를 연습해 보세요.
이 앱에 Gemini API 기능을 연결하고 싶어.
API 키가 코드나 GitHub 저장소에 절대 노출되지 않도록 내 PC의 .env 파일에 GEMINI_API_KEY를 보관하고, .gitignore에 .env를 추가해 줘.
교실 PC에서 로컬로 실행해 안전하게 Gemini API를 호출할 수 있는 구조를 만들고, 실행 순서를 한국어로 쉽게 정리해 줘.

7. 안전 점검 후 GitHub에 올리기 (push) 50~56분

학교 대여 노트북(Intune 게스트 모드)은 로그아웃하거나 전원을 끄면 로컬 작업 폴더가 초기화될 수 있습니다. 수정한 코드는 반드시 GitHub에 push해 두고, 그 전에 올라갈 파일 목록을 먼저 확인합니다. 학생 데이터가 담긴 .json 파일이나 API 키가 들어 있는 .env 파일은 절대 포함되면 안 됩니다.

git status로 이번에 GitHub에 올라갈 파일 목록을 보여 주고, 바뀐 내용을 쉽게 설명해 줘.
학생 개인정보, 실제 데이터 JSON 파일, .env 파일, API 키, 비밀번호가 포함되지 않았는지 먼저 확인해 줘.
문제가 없으면 커밋 메시지를 제안하고, 내 확인을 받은 뒤 commit과 push를 진행해 줘.

GitHub 인증 창이 뜨면 브라우저에서 직접 로그인합니다. 비밀번호나 인증 코드는 AI 대화창에 입력하지 않습니다. 푸시가 끝난 뒤 GitHub 저장소에서 파일이 잘 올라갔는지, 공개 주소(정적 앱인 경우)에 반영되었는지 확인합니다. 푸시가 막히면 2회차처럼 GitHub 웹의 Add file → Upload files로 코드 파일만 올릴 수 있습니다.

8. 마무리와 심화과정으로 이어가기 56~60분

  • 오늘 고친 점과 앞으로 교실에서 활용해 보고 싶은 장면을 한 줄씩 나눕니다.
  • 대여 노트북(게스트 모드) 마무리: 수정한 코드가 GitHub에 올라간 것을 확인한 뒤, Antigravity(개인 Gmail), GitHub에서 로그아웃하고 연습용 JSON 파일과 브라우저에 입력한 API 키를 꼭 삭제합니다.
  • 이 3주 과정 사이트는 다음 스터디의 기본 교재로 계속 활용하며, 교실 PC 로컬 도구·안전한 API 연동·구글 시트 연동 등 심화과정으로 이어갈 예정입니다. 자세한 방향은 다음 단계에서 확인하세요.
꼭 지켜 주세요 학생 개인정보(이름·번호·평가 결과)와 API 키·비밀번호는 앱 코드와 GitHub 저장소에 넣지 않습니다. 로컬 JSON 데이터와 .env 파일은 반드시 .gitignore로 제외하고, 교실 PC에만 안전하게 보관합니다.
